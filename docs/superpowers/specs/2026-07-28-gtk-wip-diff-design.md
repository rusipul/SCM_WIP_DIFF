# GTK WIP 일일 비교 리포트 도구 설계

## 배경 및 목적

Greatek(GTK)에서 매일 전달되는 `<YYMMDD> GTK WIP.xlsx` 파일은 반도체 웨이퍼 랏별 공정 진행 현황(WIP)을 담고 있다. 항목 수가 많아 전일 대비 어떤 랏이 어느 공정으로 진행됐는지 수작업으로 확인하기 어렵다. 어제 파일과 오늘 파일 두 개를 선택하면 자동으로 비교하여 변동 내역을 리포트하고, 오늘 파일에 변경된 셀을 시각적으로 표시해주는 데스크톱 도구를 만든다.

## 대상 파일 구조 (실제 샘플 분석 결과)

- 파일명 패턴: `<YYMMDD> GTK WIP.xlsx` (예: `260721 GTK WIP.xlsx`)
- 시트 하나에 서로 다른 5개의 리포트가 세로로 이어붙어 있음: **Report for Assy or Turn-key WIP**(대상) → Pin count 요약 → Hold Wafer Status → PFT WIP → TAP WIP. 뒤의 4개는 컬럼 구조가 완전히 다르므로 파싱 대상에서 제외해야 한다.
- 대상 표 헤더: "Report for Assy or Turn-key WIP" 텍스트가 있는 행을 기준(anchor)으로 상대 위치 계산 (고정 행 번호 하드코딩 금지 — 랏 개수가 파일마다 달라 데이터 길이가 바뀜).
- 컬럼 구성:
  - A: MO No. / B: Wafer Lot No. / C: Device No.
  - G: 생산 투입전 수량(Qty) / H: 투입 수량(In Qty)
  - I~K: 전공정 (Saw, Mount, Bond)
  - L~AB: 후공정 (Mold, Mark, Pmc, Trim, B-T/P, T/P, P-INS1, MARK_2, P-INS, Mount, Form, OS, Test, L/S, F/V, TR)
  - AC~AD: 완료 (Stock-TR, Stock-Non TR)
  - AE: Fail-Stock / AF: Fail-Loss / AG: 전체 완료 수량(OUT Q'TY)
  - AH: 시작일(RCVD DATE) / AI: 완료요청일(REQ DATE) / AJ: 쉬핑일(SHIP DATE)
- 전공정/후공정/완료 그룹 경계는 anchor 바로 다음 행(그룹헤더행)의 병합 셀 범위(샘플 기준 `I3:K3`, `L3:AB3`, `AC3:AD3`)를 읽어 동적으로 결정한다 (향후 컬럼이 추가/삭제되어도 코드 수정 불필요).
- **중복 키 이슈**: 같은 웨이퍼 랏(B)+디바이스(C) 조합이 서브랏(다른 MO No.)으로 나뉘어 여러 행에 나타나는 경우가 실제 데이터에 존재함 (예: `1B4686/TMP1204`가 MO `TNF0255623345E`, `TNF0255623344E` 두 행으로 존재). 따라서 비교 키는 **A(MO No.) + B(Lot No.) + C(Device No.)** 조합을 사용한다.
  - 극히 드물지만(실측 샘플 172개 중 2쌍) A+B+C까지 동일한 경우도 있었다(MO가 비어있고 PO도 동일한 경우 포함, 구분 가능한 다른 컬럼이 데이터에 없음). 이 경우 **같은 (A,B,C) 키 내에서 파일 내 등장 순서**(1번째, 2번째, ...)를 키에 추가해 최종 고유 키로 삼는다: `(A, B, C, occurrence_index)`. 어제/오늘 파일 각각에서 등장 순서를 계산해 매칭한다.
- 데이터 종료 조건: B열(Lot No.)이 비는 첫 행에서 데이터 끝으로 판단 (이후 다른 리포트 블록 자동 제외).

## 아키텍처

```
scm_wip_diff/
├── main.py          # 진입점, GUI 실행
├── gui.py            # tkinter 화면 (파일 선택, 결과 미리보기, 실행)
├── parser.py         # xlsx에서 대상 표만 추출
├── comparator.py     # 두 데이터셋 비교 → 변동 목록 생성
└── report.py         # 엑셀 리포트 생성 + 오늘 파일 하이라이트
```

모듈형 구조를 택한 이유: 표 파싱(다중 리포트 중 첫 표만 추출), 키 매칭(MO+Lot+Device), 컬럼별 diff, 엑셀 스타일링 등 로직이 각각 독립적으로 검증/수정될 필요가 있기 때문. GUI는 위 로직들을 호출하는 얇은 레이어로 유지한다.

## 데이터 파싱 (`parser.py`)

1. "Report for Assy or Turn-key WIP" 텍스트가 있는 셀을 찾아 anchor로 삼는다.
2. anchor 기준 상대 위치로 그룹헤더행(전공정/후공정/완료 병합셀), 서브헤더행(Saw/Mount/Bond 등 컬럼명), 데이터 시작행을 계산한다.
3. 병합 셀 범위를 읽어 전공정/후공정/완료 컬럼 그룹을 동적으로 구성한다.
4. 데이터는 B열이 빌 때까지 읽으며, 각 행을 다음 형태로 변환한다:
   ```python
   {
     "key": (mo, lot, device),  # 공백 strip
     "row": <엑셀 행 번호>,
     "process_values": {"I(Saw)": 0, "J(Mount)": 0, ..., "AD(Stock)": 24627},
   }
   ```
5. 숫자 컬럼 값은 `int(value) or 0`으로 정규화한다 (None/빈 값은 0).
6. anchor를 찾지 못하면 명확한 예외를 발생시켜 GUI에서 사용자에게 안내한다.

## 비교 로직 (`comparator.py`)

- **단계별 합계 비교**: 어제/오늘 각각 전공정·후공정·완료 그룹의 전체 수량 합계를 구하고 증감을 계산한다.
- **랏 단위 비교**: 동일 키가 양쪽에 있으면 I~AD 컬럼을 하나씩 비교해 값이 달라진 컬럼만 `(컬럼명, 어제값, 오늘값)`으로 기록한다. 비교 범위는 **I~AD만** (G,H,AE~AJ는 참고 표시만 하고 변동 감지 대상에서는 제외).
  - 물량이 공정을 진행하면서 한 컬럼에서 감소하고 다음 컬럼에서 증가하는 것(예: Saw(I) 347,638→0, Die Mount(J) 316,800→664,438는 Saw에서 Die Mount로 물량이 이동한 것)이 리포트의 핵심 관심사다. 이를 "A→B 이동" 형태로 자동 추론하지 않고, **변경된 컬럼들을 I→AD 컬럼 순서 그대로 나열**하는 것만으로 표현한다. 하루에 3개 이상 컬럼이 동시에 변하는 랏(예: 실제 샘플의 `1B3A98`)도 있어 1:1 이동 추론은 모호해질 수 있기 때문에, 순서대로 나열해 사용자가 직접 흐름을 읽도록 한다.
- **신규/삭제 랏**: 오늘에만 있는 키는 "신규", 어제에만 있는 키는 "삭제(출하/제외 추정)"로 별도 목록화한다.
- 출력 구조:
  ```python
  {
    "stage_summary": {"전공정": {...}, "후공정": {...}, "완료": {...}},
    "changed_lots": [{"key": (mo,lot,device), "row_in_today": 23, "changes": [("Mold(L)", 0, 500), ...]}],
    "new_lots": [{"key": ..., "row_in_today": 45}],
    "removed_lots": [{"key": ..., "row_in_yesterday": 12}],
  }
  ```

## 리포트 출력 (`report.py`)

**① 변동리포트 엑셀 파일** (`<오늘날짜>_GTK_WIP_변동리포트.xlsx`, 오늘 파일과 같은 폴더에 저장)
- 요약 시트: 전공정/후공정/완료 단계별 합계(어제/오늘/증감), 변경된 랏 수, 신규 랏 수, 삭제된 랏 수
- 변동랏 시트: 랏별 변경 내역을 긴 표 형태로 (MO, 랏번호, 디바이스, 변경 컬럼, 어제값, 오늘값)
- 신규랏 시트: 신규 랏의 키 + 현재 공정값 스냅샷
- 삭제랏 시트: 삭제된 랏의 키 + 어제 시점 공정값 스냅샷

**② 하이라이트된 오늘 파일** (`<오늘 파일명>_변동표시.xlsx`, 오늘 파일과 같은 폴더에 저장, 원본은 건드리지 않음)
- 원본 서식 유지, 값이 바뀐 셀만 빨간색 배경(`FFFF0000`)
- 신규 랏은 행 전체를 파란색 계열 배경(`FFADD8E6`, 연한 파랑)으로 표시
- 원본 파일 자체는 수정하지 않고 항상 새 파일로 저장

## GUI (`gui.py`)

tkinter 단일 창:
- "어제 파일 선택" / "오늘 파일 선택" 버튼 + 파일 다이얼로그
- "비교 실행" 버튼
- 결과 미리보기 (요약 통계 + 변경/신규/삭제 랏 표, Treeview)
- 실행 완료 시 저장된 두 파일 경로 안내

## 오류 처리

- 대상 표를 찾지 못하거나 필수 컬럼이 없으면 팝업으로 원인을 안내하고 중단한다.
- 저장하려는 파일이 이미 엑셀에서 열려 있어 쓰기 실패하면 "파일이 열려있어 저장할 수 없습니다"로 안내한다.
- 숫자가 아닌 값이 공정 컬럼에 들어있으면 0으로 처리한다.
- 어제/오늘 파일의 랏 구성이 크게 다르더라도(예: 잘못된 파일 선택) 경고만 하고 진행은 허용한다.

## 테스트 방침

- `parser.py`, `comparator.py`: 실제 제공된 샘플 파일(`260721 GTK WIP.xlsx`, `260722 GTK WIP.xlsx`)을 픽스처로 사용한 pytest 단위 테스트.
- `report.py`: 생성된 엑셀을 다시 openpyxl로 열어 셀 값/색상 검증.
- `gui.py`: 얇은 연결 코드이므로 자동 테스트 제외, 수동 확인.

## 알려진 한계

- MO No.(A열)가 비어있다가 다음 날 값이 채워지는 경우, B+C는 동일해도 키(A+B+C+순번)가 달라져 "삭제 1건 + 신규 1건"으로 표시된다 (실제 샘플에서 `1B3C76/TMP1230` 랏 1건 확인됨). 같은 랏에 MO 번호가 뒤늦게 배정된 것으로 추정되며, 자동으로 병합 처리하지 않고 사용자가 신규/삭제 목록에서 육안으로 확인하도록 한다.

## 범위 밖(Out of Scope)

- 파일명(`260721` 등)을 이용한 자동 파일 탐지/매칭은 하지 않는다. 사용자가 GUI에서 직접 두 파일을 선택한다.
- `ATX WIP.xlsx` 등 다른 파일명 패턴은 이번 범위에 포함하지 않는다.
- G, H, AE~AJ 컬럼은 참고 표시만 하며 변동 감지 대상이 아니다.
